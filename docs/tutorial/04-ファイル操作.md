# 04. ファイル操作

この章では Claude Code に **ファイルを作ってもらう・直してもらう** ことを学びます。

ここから「実際にコードが変わる」操作に入るので、**安全対策** の話もします。

---

## 安全対策その1：git を使う

`line-group-bot` フォルダは「git」というバージョン管理ツールで管理されています。
これがあれば、**間違って変なファイルになっても、すぐ元に戻せます**。

起動前に状態を確認しましょう（ターミナルで `claude` を抜けるか、別タブで実行）。

```bash
git status
```

`nothing to commit, working tree clean` と出ていれば、現状は綺麗な状態です。

> 💡 「綺麗な状態」から作業を始めると、何を変えたかが分かりやすくなります。

---

## 安全対策その2：Claude Code は確認してくれる

ファイルを書き換える前、Claude Code は **「この変更で良いですか？」と聞いてきます**。

```
Edit file: server.mjs
─────────────────────
- const PORT = 3000;
+ const PORT = 8080;
─────────────────────
Allow this edit? (y/n)
```

**赤い行が削除、緑の行が追加** です。納得できたら `y`、違うと思ったら `n` を押します。

> ⚠️ 慣れないうちは、毎回中身を確認してから `y` を押しましょう。

---

## 演習1: 新しいファイルを作ってもらう

`.env.example` を見て、本番用の `.env` を作ってもらいましょう。

Claude Code に：

```
.env.example をコピーして .env というファイルを作って。
中身は空欄のままで OK
```

実行後、ターミナル（別タブ）で確認：

```bash
ls -la .env
```

ファイルが存在すれば成功です。

> 💡 **なぜ .env？**：パスワードや API キーは安全のためコードに直接書きません。`.env` という別ファイルに分けて、git でも管理しないようにします。`.gitignore` を見ると `.env` が除外されているのが分かります。

---

## 演習2: ファイルの一部を書き換えてもらう

`.env` の中身を埋めてみましょう（本物のキーは入れず、ダミーで OK）。

```
.env の PORT を 8080 に設定して
```

実行されると、ファイルが書き換わります。確認しましょう。

```
.env の中身を見せて
```

`PORT=8080` になっていれば成功です。

---

## 演習3: 説明文を追加してもらう

`server.mjs` を題材に、コメントを足してもらいます。

```
server.mjs の handleEvent 関数の上に、日本語で何をする関数かのコメントを1行追加して
```

差分が表示されたら確認して `y`。

確認は：

```
server.mjs の handleEvent 周辺を見せて
```

---

## 演習4: 元に戻す

「やっぱり気に入らない」というときは、git で戻せます。Claude Code に：

```
git で server.mjs の変更を取り消して、元に戻して
```

または、自分でターミナルから：

```bash
git checkout server.mjs
```

これで変更前の状態に戻ります。

> 💡 **これが git の最強ポイント**：いつでも元に戻せるから、安心してチャレンジできます。

---

## 演習5: まとめて整える

複数の変更を一度にお願いすることもできます。

```
.env.example を見て、README.md に「環境変数の設定方法」のセクションを追加して。
各環境変数の意味も日本語で書いて。
```

複数ファイルにまたがる作業でも、Claude Code は順序立てて進めてくれます。

---

## ファイル操作のコツ

### ✅ こうすると良い

- **対象ファイルを明示する**：「`server.mjs` の」「`lib/ai.mjs` の」
- **どこを変えるか言う**：「先頭に」「`handleEvent` の中に」
- **目的を伝える**：「ログを見やすくするため」「タイムアウトを長くするため」

### ❌ こうすると伝わりにくい

- 「コード直して」（どのファイル？何を？）
- 「全部いい感じにして」（範囲が広すぎる）
- 「あれをそれに」（指示語は AI に通じにくい）

---

## 「危ない操作」への対応

Claude Code は、以下のような操作の前に **必ず確認** します。

- ファイルの削除（`rm`）
- 強制プッシュ（`git push --force`）
- データベースの DROP
- パッケージの削除

確認なしに進んでほしくないと思ったら、「**まず計画だけ立てて、実行はしないで**」と最初に伝えるのが安全です。
