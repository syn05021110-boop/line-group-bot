## 1. なぜ「自分で持つ」のか

有料の予約投稿ツールは、画面から投稿文を入れて日時を選ぶだけで使えます。手軽さでは、そちらが上です。

それでも私が自分で持つことにした理由は、3つあります。

1. **月額がかからない**：公式APIを使い、Render の無料枠で動かしているので、ツールの月額はかかりません
2. **動き方を自分で決められる**：「深夜は出さない」「間隔をばらつかせる」「同じ投稿が続かないようにする」を、思いどおりに組める
3. **中身が分かる**：うまく動かないとき、どこを見ればいいか分かる

3つ目が、実はいちばん大きいです。
私は以前、自作ツール「副業ドラフト」で、AIのAPIキーに有効期限があることに気づかず、約7週間、最初のボタンでエラーになって誰も使えない状態を放置していました。
仕組みを自分で持つなら、「何が期限切れになるのか」「止まったらどこに出るのか」を知っておく必要がある。これはそのときの反省です。

逆に言えば、自分で持つと、止まったときに気づくのも直すのも自分です。
ここは有料ツールとの一番の違いなので、先に書いておきます。

## 2. 全体の仕組み

[[img:p05_flow.png]]

動きはシンプルです。

1. 投稿したい文章を、1つのファイルに並べておく
2. アプリが10分ごとに「そろそろ投稿する時間か？」を確認する
3. 時間になっていたら、ファイルから1本選んで、公式API で Threads に投稿する
4. 次の投稿時刻を、ランダムに決めて記録する
5. ついでに、自分自身のURLにアクセスして、サーバーが眠らないようにする

登場するのは次の3つだけです。

- **Threads のアカウント**：投稿する先
- **Meta の開発者アプリとアクセストークン**：アプリが「あなたの代わりに投稿していい」と認められるための鍵
- **Render**：アプリを24時間動かしておく場所（無料枠）

## 3. 必要なものと、それぞれの注意点

### Threads のアカウント

普段使っているアカウントで大丈夫です。
自動投稿は、自分のアカウントに、自分の書いた文章を出すためだけに使います。

### Meta の開発者アプリとアクセストークン

Threads の公式API を使うには、Meta の開発者向けサイトでアプリを作り、Threads の利用を有効にして、自分のアカウントで許可を出し、アクセストークンを発行します。

画面の細かい手順は、ここでは書きません。
Meta の開発者向け画面は時々変わるので、私が今見ているボタン名を書いても、あなたが見るときには違っているかもしれないからです。

代わりに、公式ドキュメントを見てください。
https://developers.facebook.com/docs/threads

分からないところは、AIアシスタントに「この公式ドキュメントを読んで、Threads API でテキスト投稿するためのトークンを取る手順を、今の画面に合わせて教えて」と頼むのが確実です。画面のスクリーンショットを見せながら進めると迷いにくくなります。

押さえておきたいのは、次の3点です。

- 投稿には、投稿用の権限が付いたトークンが必要
- 短い期限のトークンと、長い期限のトークンがある。自動投稿には長い期限のもの（長期トークン）を使う
- 長期トークンにも有効期限がある。私のアプリのコードでは60日として扱い、期限が切れる前に更新する入口を用意している。正確な期限と更新方法は、公式ドキュメントで確認する

**トークンは、パスワードと同じものだと思ってください。**
チャットに貼らない、画面を人に見せない、ファイルに書いて公開しない。これは後の「合言葉」の章でもう一度書きます。

### Render の無料枠

Render は、作ったアプリをインターネット上で動かしておけるサービスです。無料枠があります。

ただし、無料枠には大事な性質があります。
**しばらくアクセスがないと、アプリが眠ります。**

眠っている間は、アプリの中の時計も止まります。
つまり、「10分ごとに確認する」仕組みを入れても、眠っていたら何も起きません。

私のアプリでは、この問題をこう解決しています。

- 10分ごとに投稿の確認をするついでに、**自分自身の公開URLにアクセスする**
- 外から見ると「10分おきにアクセスが来ている」ので、眠らない
- Render は自分の公開URLを環境変数で渡してくれるので、それを使う（手動で指定もできる）

最初は、外部の cron サービス（決まった時刻にURLを叩いてくれる無料サービス）に頼っていました。
あとから、外部に頼らずアプリ自身で定期的に動いて、自分を起こし続ける形に変えました。外部の cron は、いざというときの予備として、今も叩ける入口だけ残しています。

無料枠の条件（眠るまでの時間や、1か月に動かせる時間など）は変わることがあります。
必ず Render の料金ページとドキュメントで、今の条件を確認してください。

## 4. 私が決めた5つの設計と、その理由

ここからが本題です。
AIにコードを書いてもらうときに、私が「こう動いてほしい」と決めたことを、1つずつ理由と一緒に書きます。

### ① 投稿文は、テキストのファイルに並べておく

投稿したい文章は、1つのファイルに、文章を並べるだけの形にしています。

```
[
  "1本目の投稿文",
  "2本目の投稿文。\n\n改行は \\n で書く",
  "3本目の投稿文"
]
```

データベースは使っていません。理由は単純で、

- 中身が一目で分かる
- 追加も削除も、ファイルを1行直すだけ
- AIに「このファイルに、こういう投稿を10本足して」と頼みやすい

からです。今は40本ほど入れています。

1本あたりの文字数には上限があるので、アプリ側で「上限を超えていたら投稿しない」チェックを入れています（私のコードでは500字で判定。上限は公式ドキュメントで確認してください）。

### ② 間隔は、ランダムにする

[[img:p05_timeline.png]]

ここは何度も変えました。git の履歴に残っている順に書きます。

1. **最初：4時間おきの固定**
   決まった間隔で、機械的に出していました
2. **次：5〜9時間のあいだでランダム**
   毎回ぴったり同じ間隔で出るのは、いかにも機械っぽい。人が投稿するなら、時間はばらつくはず。そう考えて、間隔をランダムにしました
3. **次：4〜7時間のあいだでランダム**
   もう少し本数を出したくて、1日3〜4本になるように縮めました
4. **今：10〜16時間のあいだでランダム**
   自動投稿は1日1〜2本に減らしました

最後に減らした理由は、**自分で手動で出す画像つきの投稿があるから**です。
自動で3〜4本、そこに手動の投稿が加わると、1日の本数がかなり多くなります。
自動を1〜2本にして、手動と合わせて**1日2〜3本**に収まるようにしました。

ここで伝えたいのは、「10〜16時間が正解」ということではありません。
**自動の本数は、手動で出す本数と合わせて決める**、ということです。
自分が1日に何本くらい出したいかを先に決めて、そこから逆算してください。

間隔の最短・最長は、コードを直さなくても設定（環境変数）で変えられるようにしてあります。
様子を見ながら調整するなら、ここは必ず外から変えられるようにしておくのがおすすめです。

### ③ 直近に出したものは避ける

最初は、ファイルの上から順番に出していました。
今は、**ランダムに1本選ぶ。ただし、直近に出した数本は選ばない**、という形です。

- 同じ投稿が短いあいだに2回出る、ということが起きにくい
- 順番どおりに出すより、並びが単調にならない

「直近の何本を避けるか」は、投稿の総数に合わせて自動で決めています（私のコードでは総数の3分の1、ただし3〜8本の範囲）。
投稿文が少ないと避けられる数も少なくなるので、**投稿文はある程度の本数を用意しておく**ほうが、この仕組みは活きます。

### ④ 深夜1〜6時は投稿しない

日本時間の1時から6時は、投稿しません。

人が寝ている時間に投稿が出続けるのは不自然ですし、読まれる時間でもありません。
この時間帯は「投稿の時間が来ていても、保留する」だけにしていて、明けてから最初の確認のときに出ます。

1つ注意があります。
保留した分は「明けた直後」に出るので、朝6時台に投稿が出ることがあります。これが気になる場合は、止める時間帯を広げてください。
この時間帯も、設定で変えられるようにしています。

また、サーバーの時計は日本時間とは限りません。**「日本時間で判定して」とAIに明示する**のを忘れないでください。

### ⑤ 二重投稿を防ぐ

自動投稿で一番怖いのは、同じ投稿が連続で2回出ることです。
私のアプリでは、いくつかの対策を重ねています。

- **投稿処理中は、次の確認が来ても何もしない**
  アプリの中の定期確認と、外部 cron の予備の入口が、同時に動いても大丈夫なようにしています
- **「次の投稿時刻」を記録して、その時刻まではどこから呼ばれても投稿しない**
  入口を何回叩かれても、時刻前なら「待機中」と返すだけです
- **起動直後にすぐ投稿しない**
  アプリが再起動したとき（更新したときなど）、記録が消えていることがあります。そのとき、いきなり投稿せず、20〜90分後のどこかを次の投稿時刻に決めてから待ちます

3つ目は、無料サーバーならではの対策です。
Render の無料枠では、アプリを更新したり再起動したりすると、アプリが書いた記録が消えることがあります。記録が消えて「前回の投稿はいつ？」が分からなくなったとき、すぐ出してしまうと、直前に出したばかりの投稿と間隔が詰まります。だから、少し待つ形にしています。

## 5. 入口は「合言葉」で守る。合言葉は絶対に公開しない

私のアプリには、ブラウザから開ける入口がいくつかあります。

- 投稿の確認を今すぐ走らせる入口（外部 cron の予備用）
- 指定した投稿を今すぐ出す、テスト用の入口
- 次の投稿時刻や、最後に出した時刻を見る入口
- トークンを更新する入口

これらは、**合言葉を知っている人しか使えない**ようにしています。
合言葉がないと「違います」と返して、何もしません。

もし合言葉なしで誰でも叩ける状態だと、知らない人に何度も投稿されたり、トークンを更新されたりするおそれがあります。

そして、ここは私自身の反省です。

**以前、こうした鍵が、公開しているリポジトリの中に入ってしまったことがあります。**

コードを置いている場所を公開にしていると、そこに書いた文字は誰でも読めます。
鍵をファイルに直接書いてしまうと、あとで消しても、変更の履歴に残ります。

それ以来、次のことを守っています。

- 合言葉・トークン・APIキーは、**コードやファイルに直接書かない**。サーバーの環境変数に入れる
- 手元の設定ファイルに書く場合は、そのファイルを**公開の対象から外す設定**にしておく（AIに「このファイルが公開されない設定になっているか確認して」と頼めます）
- AIに頼むときも、**鍵そのものをチャットに貼らない**。「環境変数から読むようにして」と頼む
- 万が一公開してしまったら、**ファイルから消すだけでは足りない**。発行元で鍵を無効にして、新しいものに取り替える

もう1つ、見落としやすい点があります。
合言葉を、ブラウザのアドレス欄に入れて使う形（URLの後ろに付ける形）にしている場合、そのURLはブラウザの履歴に残ります。人に画面を見せるときや、URLをどこかに貼るときは気をつけてください。

## 7. 動かし始めてからの運用のコツ

[[img:p05_checklist.png]]

### 本数は「手動と合わせて」決める

先に書いたとおり、私は自動を1日1〜2本にして、手動の画像つき投稿と合わせて1日2〜3本にしています。
自動投稿は手間がかからないぶん、つい本数を増やしたくなります。でも、出しすぎて読む人に飽きられては意味がありません。

### 凍結のリスクはゼロではない、と思っておく

公式API を使っていても、Threads の利用規約やルールに反する使い方をすれば、制限を受ける可能性はあります。
どういう使い方が問題になるかは、Meta の規約と開発者向けのポリシーを確認してください。API の仕様やポリシーは変わることがあります。

私が気をつけているのは、

- 短い間隔で大量に出さない
- 同じ文章を繰り返し出さない（③の仕組み）
- 自分のアカウントに、自分の書いた文章を出すことにだけ使う

の3つです。

### 自動投稿だけにしない

自動で出る投稿は、あらかじめ用意した文章です。その日の出来事や、ふと思ったことは入っていません。

私の経験では、AIが整えた文章より、ボソッとつぶやいた一言のほうが反応があります。
自動投稿は「発信が途切れないための土台」と考えて、その日に思ったことは手で出すようにしています。

### コメントへの返事は、自分でする

自分の投稿にコメントがついたら、返事は自分でします。
私のアプリには、コメントへの返信案をAIに出してもらう機能も付けましたが、送信は必ず手動にしています。

### 他人の投稿への自動返信・自動いいねはやらない

他人の投稿に、自動で返信したり、いいねを押したりする仕組みは作っていませんし、おすすめもしません。

- 相手にとっては、機械からの返事が届くことになる
- 規約上の問題になりやすい
- そもそも、会話は自分でするから意味がある

自動化するのは「自分の投稿を、決めた間隔で出す」ところまで。ここは線を引いています。

### 定期的に確認すること

- **トークンの期限**：期限が切れると、投稿は止まります。カレンダーに更新日を入れておくのがおすすめです
- **状態を確認する入口**：週に一度でも、最後に投稿した時刻を見て、止まっていないか確かめる
- **投稿文の中身**：古くなった情報や、今の自分と合わなくなった投稿は入れ替える
- **Render の無料枠の条件**：条件が変わっていないか、たまに確認する

副業ドラフトの API キーが期限切れで約7週間止まっていたとき、私は気づきませんでした。
自動で動くものほど、止まっても静かです。**「止まっていないか見に行く」予定を、先に決めておいてください。**

## おわりに

自動投稿を自分で持つのに、エンジニアである必要はありませんでした。
必要だったのは、「どう動いてほしいか」を決めることと、動かしながら直していくことです。

私の場合も、固定4時間から始めて、今の10〜16時間になるまで、何度も変えています。
最初から正解を作ろうとしなくて大丈夫です。

まずは、6章の頼み方の「テスト投稿の入口」の部分だけをAIに渡して、1本、自分のアプリから Threads に出してみてください。
