## 1. 仕組みの全体像：画像を「ウェブページ」として作る

[[img:p03_flow.png]]

やっていることは、3段階だけです。

1. **載せる中身を文章で渡す**：見出し、箇条書き、強調したい言葉
2. **AI が HTML（ウェブページの設計図）を書く**：文字の位置、色、大きさを指定したページ
3. **画面のないブラウザで開いて、PNG として保存する**：ページのスクリーンショットを、決めたサイズぴったりで撮る

3番目の「画面のないブラウザ」は、ヘッドレス Chrome と呼ばれるものです。
ふだん使っている Chrome と同じようにページを表示できますが、ウィンドウを出さずに裏で動きます。
これに「幅1280、高さ670で開いて、写真を撮って」と命令すると、そのサイズの PNG が1枚できあがります。

この命令を書くのも、ヘッドレス Chrome を用意するのも、AI にやってもらいました。
私が覚えておく必要があったのは、「HTML で作って PNG にする」という考え方だけです。

## 2. なぜ HTML なのか

AI に直接「画像を作って」と頼む方法もあります。
それでも私が HTML を選んだ理由は3つです。

### ① 日本語の文字を、思いどおりに置ける

画像を生成する AI に日本語を入れてもらうと、文字がくずれたり、知らない字が混ざったりすることがあります。
HTML なら、文字は文字として入ります。パソコンに入っているフォント（私はヒラギノ）で、そのまま表示されます。

「ここで改行して」「この言葉だけ黄色にして」も、そのとおりになります。

### ② 何枚作っても、同じデザインになる

色や文字の大きさを最初に一度決めておけば、あとは中身を入れ替えるだけです。
7ツールの記事では、note 用5枚と Threads 用6枚を同じ決まりごとで作りました。並べると、同じ人が作った画像だと分かります。

### ③ 直すのが簡単

「この文字が枠からはみ出している」「もう少し下に寄せたい」と思ったら、AI にそう言うだけです。
HTML の数字が書き換わって、もう一度 PNG を撮り直してくれます。
1枚目から全部やり直す必要がありません。

## 3. 画像のサイズは、この3つを覚えておく

[[img:p03_sizes.png]]

私が使っているサイズです。

- **note の見出し画像：1280×670**
  note の記事一覧やSNSでシェアされたときに出る画像です
- **Threads の画像：1080×1350**
  縦長です。スマホで見たときに画面を大きく使えます。複数枚投稿もこのサイズでそろえています
- **LINE公式アカウントのリッチメニュー（大・6分割）：2500×1686**
  トーク画面の下に出るボタンの画像です。横3つ×縦2段に区切って、それぞれがボタンになります

記事の途中に入れる図解は、横幅を1280にそろえて、高さは中身に合わせて変えています（500〜780くらい）。
note の本文の画像は横幅いっぱいに表示されるので、横幅さえそろえておけば見た目がそろいます。

リッチメニューだけは注意があります。
LINE の管理画面で「6分割」を選ぶと、タップできる範囲があらかじめ決まっています。画像の区切りがその範囲とずれると、押した場所と違うボタンが反応します。
AI には「LINE の6分割テンプレートのタップ範囲と、画像の区切りをそろえて」と伝えてください。

## 4. デザインの決まりごと：迷う部分を最初に消す

毎回「何色にしよう」と考えていると、それだけで時間がなくなります。
なので、最初に決めて、それ以外は使わないことにしました。

### 私が使っている決まりごと

- **背景：紺（#0E1525）**
- **強調の色：黄（#FFD23F）だけ**。強調したい言葉、番号、矢印に使う
- **本文の文字：白**
- **補足の文字：くすんだ青灰色（#9AA7BF）**
- **カード（四角い枠）：背景より少し明るい紺（#18223A）に、細い線の枠**
- **見出し：大きく、太く**。note の図解なら44px前後、Threads なら58〜96px
- **フォント：ヒラギノ（Mac に最初から入っている日本語フォント）**

いちばん効いているのは、**強調の色を1色にしたこと**です。
色を増やすと、どこを見ればいいのか分からなくなります。黄色の部分だけ読めば言いたいことが分かる、という状態を目指しています。

「#0E1525」のような書き方は、色を番号で表したものです。
意味が分からなくても大丈夫です。この番号をそのまま AI に渡せば、同じ色になります。

自分の色を決めたい人は、次のように頼んでください。

```
私の発信用の画像に使う「デザインの決まりごと」を決めたいです。

・発信のテーマ：【例：会社員の副業とAIの使い方】
・読んでほしい人：【例：30〜40代の会社員】
・伝えたい雰囲気：【例：落ち着いていて、でも目に止まる】

次の形で出してください。
1. 背景の色、本文の文字の色、補足の文字の色、強調の色（1色だけ）を、色番号（#から始まるもの）で
2. 見出しと本文の文字の大きさの目安（note用 1280×670 と、Threads用 1080×1350 のそれぞれ）
3. この組み合わせを選んだ理由を一言ずつ

候補は2パターン出してください。
```

決まったら、その内容をメモに保存しておきます。以後、画像を頼むときに毎回貼ります。

## 5. 最初の1回：仕組みを作ってもらう

最初だけ、「HTML を PNG にする仕組み」そのものを AI に作ってもらいます。
Claude Code のように、パソコンの中でファイルを作ったりコマンドを動かしたりできる AI に、次のように頼んでください。

```
note と Threads に使う画像を、HTML で作って PNG に書き出す仕組みを作ってください。

・画像の中身は HTML で組み、ヘッドレス Chrome でスクリーンショットを撮って PNG にする
・ヘッドレス Chrome が入っていなければ、入れ方を教えてから入れてください
・作った HTML と PNG は、このフォルダの中の images というフォルダに保存
・1つのコマンドで、全部の画像を作り直せるようにしてください
・デザインの決まりごとは次のとおりです
  【4章で決めたデザインの決まりごとを貼る】

最初のテストとして、「テスト」という大きな見出しだけの 1280×670 の画像を1枚作ってください。
作ったら、できた PNG の場所を教えてください。
```

テストの1枚ができたら、実際に開いて見てください。
文字がちゃんと日本語で出ていて、サイズが合っていれば、仕組みはできています。

私の場合、AI は Python という言語で、画像ごとに HTML を組み立てて Chrome に撮らせる小さなプログラムを書きました。
中身を読めなくても問題ありません。「作り直して」と言えば、そのプログラムを動かしてくれます。

## 6. 画像のひな形（AI にそのまま渡せます）

仕組みを作ってもらうとき、または1枚だけ作ってほしいときに、このひな形を一緒に渡すと話が早くなります。
私が実際に使っている形を、読みやすく削ったものです。

```html
<!doctype html>
<html>
<head>
<meta charset="utf-8">
<style>
  * { margin: 0; padding: 0; box-sizing: border-box; }
  html, body { width: 1280px; height: 670px; overflow: hidden; }
  body {
    font-family: "Hiragino Sans", "Hiragino Kaku Gothic ProN", sans-serif;
    background: #0E1525;
    color: #FFFFFF;
  }
  .y { color: #FFD23F; }                 /* 強調の色（1色だけ） */
  .m { color: #9AA7BF; }                 /* 補足の文字 */
  .pad { position: absolute; inset: 0; padding: 64px;
         display: flex; flex-direction: column; justify-content: center; }
  .tag { align-self: flex-start; background: #FFD23F; color: #0E1525;
         font-weight: 800; font-size: 26px; border-radius: 6px; padding: 6px 14px; }
  .h { font-weight: 800; font-size: 64px; line-height: 1.28; margin-top: 22px; }
  .sub { font-weight: 600; font-size: 28px; margin-top: 22px; }
  .card { background: #18223A; border: 1px solid #2B3858; border-radius: 14px; }
</style>
</head>
<body>
  <div class="pad">
    <div class="tag">ラベル（例：非エンジニアの実録）</div>
    <div class="h">見出しの1行目<br><span class="y">強調したい言葉</span>を入れる</div>
    <div class="sub m">補足の一文</div>
  </div>
</body>
</html>
```

ポイントは3つです。

- `width` と `height` に画像のサイズを書いておく（Threads なら 1080px と 1350px）
- `overflow: hidden` で、サイズの外にはみ出した部分を切る
- 色は上の5色以外を使わない

AI に渡すときは、こう添えます。

```
このひな形のデザイン（色・フォント・余白）を守って、画像を作ってください。
サイズと中身だけ変えてください。
```

## 7. AI への頼み方（コピペ用）

ここからは、私が画像を作るときに使っている頼み方です。
【 】の中を書き換えて使ってください。

### ① 箇条書きを、カード型の図解にする

記事の中の「ポイントは4つ」のような部分を、図にしたいときに使います。

```
次の4つのポイントを、カード型の図解にして、1280×720 の PNG で書き出してください。

・図の見出し：【例：つまずいたのは、ここ4か所】
・ポイント：
  1. 【短い見出し】→【一言の説明】
  2. 【短い見出し】→【一言の説明】
  3. 【短い見出し】→【一言の説明】
  4. 【短い見出し】→【一言の説明】

・2列×2段のカードに並べて、番号は強調の色にしてください
・デザインは、いつものひな形に合わせてください
```

### ② note の見出し画像を作る

```
note の見出し画像を 1280×670 の PNG で作ってください。

・記事のタイトル：【タイトル】
・画像に入れる見出し：【タイトルを2〜3行に縮めたもの】
・強調する言葉：【黄色にしたい言葉】
・左上のラベル：【例：やってみた／実録／保存版】
・下の補足：【一文】

見出しは3行以内。1行が長くなりすぎないように、意味の切れ目で改行してください。
```

### ③ Threads の複数枚投稿を作る

```
Threads の複数枚投稿用に、1080×1350 の画像を6枚作ってください。

・テーマ：【例：Claude Code にツールを7つ入れた話】
・1枚目：表紙。大きな見出しと、続きを読みたくなる一言
・2〜5枚目：中身。1枚に言いたいことは1つだけ
  2枚目：【内容】
  3枚目：【内容】
  4枚目：【内容】
  5枚目：【内容】
・6枚目：まとめと、「続きは返信欄に」などの案内

・すべての画像の右下に「1/6」のようなページ番号を入れてください
・左下には【シリーズ名】を小さく入れてください
・6枚とも、同じデザイン・同じ余白でそろえてください
```

ページ番号を入れておくと、スマホで横にめくる人が「あと何枚あるか」が分かります。

### ④ 手順や流れを、矢印の図にする

```
次の流れを、左から右に矢印でつないだ図にして、横幅1280の PNG で書き出してください。高さは中身に合わせてください。

【1つ目】→【2つ目】→【3つ目】→【4つ目】

・それぞれの箱に、太字の見出しと、下に小さい説明を入れてください
・いちばん大事な箱だけ、枠を強調の色にしてください：【どれか】
・図の下に、補足の一文を入れてください：【一文】
```

### ⑤ はみ出しがないか確認して直してもらう

これはいちばんよく使います。

```
作った画像を全部開いて、次の点を確認してください。

・文字が枠やカードからはみ出していないか
・画像の端で文字が切れていないか
・言葉の途中で改行されていないか
・下のほうに大きな空白が残っていないか

問題があれば直して、もう一度 PNG を作り直してください。
直した画像と、何を直したかを一覧で教えてください。
```

AI が PNG を見られる環境なら、自分で開いて確認してくれます。
ただし、AI の「問題ありません」をそのまま信じないでください。次の章に書いたとおり、最後は自分の目で見ます。

### ⑥ 同じ中身で、別のサイズも作る

```
いま作った note 用の図解（1280×【高さ】）と同じ中身で、
Threads 用の 1080×1350 の縦長バージョンも作ってください。

・縦長になるので、横並びのカードは縦並びに変えてください
・文字は note 用より大きくしてください（スマホで読むため）
```

## 8. 出来上がりは、全部の画像を自分で見る

[[img:p03_checklist.png]]

ここがいちばん大事です。

AI が作った画像は、**1枚ずつ、実際に開いて見てください。**
約20枚作ったうち、1回目でそのまま使えたものばかりではありませんでした。
私が実際に引っかかったのは、次の4つです。

### ① 文字がはみ出す

見出しが長いと、カードの枠や画像の端から文字がはみ出します。
ひな形で `overflow: hidden` にしているので、はみ出した部分は切れて消えます。つまり、**エラーにならずに、文字が欠けたまま画像ができてしまいます。**

直し方：
- 見出しを短くする（いちばん確実）
- AI に「この画像の見出しがはみ出しているので、文字を小さくするか、2行に分けて」と頼む

### ② 変なところで改行される

言葉の途中で折り返されて、たとえば「副業」の「副」だけが前の行に残る、といったことが起きます。
横幅に収まらないと、ブラウザが自動で折り返すからです。

直し方：
- 改行したい場所を、自分で決めて AI に伝える（「『全部入れたら、』のあとで改行して」）
- 「この行は折り返さないで」と頼む（HTML の `white-space: nowrap` という指定を入れてくれます。ただし、そのぶんはみ出しやすくなるので①も確認）

### ③ 余白が空きすぎる

中身が少ないのに画像の高さが大きいと、下半分が空っぽの画像になります。
高さを先に決めて頼むと起きやすくなります。

直し方：
- 「下に空白が残っているので、高さを中身に合わせて縮めて」と頼む
- または「カードをもう少し大きく、文字も大きくして、空白を埋めて」と頼む

### ④ 暗い背景の上のリンクが読めない

紺の背景の上にリンク（URL）を置いたら、文字が背景に沈んで読みにくくなりました。
リンクの色を特に指定しないと、暗い背景では見えにくい色で表示されることがあります。

直し方：
- 「リンクの色を、白か強調の色にして」と頼む
- そもそも画像の中に長い URL を入れない。案内は「リンクは返信欄に」のように文章で書く

### 確認のしかた

- PNG を**実際のサイズで**開く（小さいサムネイルだと、はみ出しに気づけません）
- スマホに送って、スマホの画面でも見る。Threads の画像は特に
- 1枚ずつ、上の4つを順番に見る

AI には⑤の頼み方で先に確認してもらい、そのあと自分で全部見る。この2段構えにしています。

## 9. note に貼るときは「貼り付けページ」を作る

画像ができても、もう1つ面倒なことがあります。
記事の本文を note に貼ると、見出しや太字が消えてしまうことです。

私は AI に書いてもらった記事を、テキストのファイル（マークダウンという書き方）で持っています。
これをそのまま note に貼ると、「## 」や「**」といった記号が文字として出てしまいます。

そこで、**書式付きのままコピーできる「貼り付けページ」**を AI に作ってもらいました。

中身はこうなっています。

- ブラウザで開くと、記事が見出し・太字・箇条書きつきで表示される
- 画像を入れる位置で区切ってあって、区切りごとに「本文1をコピー」「本文2をコピー」のボタンがある
- 画像の位置には青いラベルで「ここに画像を挿入：ファイル名」と出て、実際の画像も表示される
- 見出し画像は「見出し画像に設定」と出る
- 記事の最初にある、価格や事実確認などの自分用メモは、コピーの対象から外れる

使うときは、ボタンを上から順に押して、note の編集画面に貼り、青いラベルの位置で画像を入れるだけです。

頼み方はこれです。

```
この記事のファイルから、note に書式付きで貼り付けるためのページ（HTML）を作ってください。

・見出し（## と ###）、太字、箇条書き、コードの囲みを、note に貼ったときに崩れない形で表示する
・記事の中の [[img:ファイル名]] の行で区切り、区切りごとに「本文◯をコピー」ボタンを付ける
・ボタンを押すと、その区切りの本文が書式付きでコピーされる
・[[img:]] の位置には、青いラベルで「ここに画像を挿入：ファイル名」と表示し、images フォルダの画像も表示する
・ファイル名に eyecatch が入っている画像は「見出し画像に設定」と表示する
・最初の「---」より前にある「> 」で始まる行は、自分用のメモなのでコピーの対象から外す
・タイトルにも、コピー用のボタンを付ける
・ページの一番上に、使い方を3行で書く

別の記事でも使えるように、記事のファイル名を指定して作り直せるようにしてください。
```

note は表（縦横のマス目）に対応していないので、記事の中では表を使わず、箇条書きにしておくのがおすすめです。
それから、貼ったあとに見出しが普通の文字になっていたら、note の編集画面でその行を選んで「大見出し」を設定し直してください。

## 10. 私の作業の流れ

最後に、1本の記事で画像を作るときの流れをまとめます。

1. **記事を書き終える**：画像を入れたい場所に `[[img:p03_flow.png]]` のような目印を入れておく
2. **画像ごとの中身をメモする**：見出し、載せる言葉、強調する言葉。記事の最後に「画像メモ」として書いておく
3. **AI に頼む**：7章の頼み方に、画像メモを貼る
4. **AI に確認させる**：⑤の頼み方
5. **自分で全部見る**：8章の4つを確認。直したいところを伝える
6. **Threads 用も作る**：必要なら⑥の頼み方で縦長にする
7. **貼り付けページを作って、note に貼る**

画像メモを記事と一緒に書いておくと、あとから「この画像、何を載せるんだったっけ」とならずに済みます。
あとで作り直したくなったときも、メモを直して AI に渡すだけです。

## おわりに

デザインが苦手でも、画像は作れます。

大事なのは、
- 画像を「描く」のではなく、中身を文章で渡して HTML で組んでもらうこと
- 色と文字の決まりごとを最初に決めて、変えないこと
- 出来上がりを、1枚ずつ自分の目で見ること

の3つです。

正直に書くと、画像を入れたことで反応がどれだけ変わったかは、まだ分かっていません。
ただ、「画像がないから投稿できない」で止まることは、なくなりました。
