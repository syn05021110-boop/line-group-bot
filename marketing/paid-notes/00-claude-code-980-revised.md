## 第1章｜Claude Codeとは何か、なぜ今やるべきか

### Claude Codeを一言で言うと

「指示を出すと、自分のPCで実際に作業をやってくれるAI」

ChatGPTとの違いを、はっきりさせとく。

- ChatGPT：質問→答えが返る（会話の中で完結）
- Claude Code：指示→実際に作業する（ファイル作る、コード書く、実行する）

たとえば。
「note記事のタイトルを考えるツール作って」って指示すると、
Claude Codeは実際にコードを書いて、ファイルを作って、
動かせる状態にしてくれる。

「いやコード書けないんだけど」
って思った人、安心してほしい。

コードを書くのはClaude Codeの仕事。
あなたの仕事は「何を作りたいか」を伝えて、出てきたものを確かめること。

これが"AIに働かせる"の意味。

### なぜChatGPTじゃダメなのか

ChatGPTは便利。でも、こういうことは苦手。

- 1回の会話で完結する
- ファイルを作って残せない
- 実際に何かを"動かす"ことができない
- 自分のPC上で作業してくれない

つまり、ChatGPTは"質問の道具"。
Claude Codeは"作業の道具"。

道具のレイヤーが違う。

### なぜ"今"やるべきか

理由は2つ。

【1】まだ非エンジニアで使っている人が少ない
Claude Codeは元々エンジニア向けのツールとして広まった。
だから「コード書けない層」で使いこなしている人は、まだ多くない。

【2】この先、使えて当たり前の道具になっていく
AIに作業を任せる道具は、どんどん身近になってる。
早めに触っておけば、慣れた状態で波に乗れる。

これが俺の感覚です。

### よくある3つの誤解を先に潰しておく

ここで読み進める前に、よく聞かれる誤解を潰しておく。
俺自身、最初これで足止め食らったから。

誤解①「ChatGPTで足りるんじゃないの?」
→ 足りない場面が多い。
ChatGPTは"質問の場"であって"作業の場"じゃない。
ファイルを作る・動かすところまでやらせたいなら、Claude Codeの出番。

誤解②「コード書けない自分には無理でしょ?」
→ 逆。コード書けない人ほど価値が出る。
書けない人は「全部任せるしかない」から、指示を出して確かめる使い方に自然となる。

誤解③「忙しい社畜には無理でしょ?」
→ 忙しい社畜こそ向いてる。
指示を出しておけば、作業はAIが進める。
自分は出てきたものを確かめるだけ。

この3つに該当して諦めかけてる人、もう少しだけ読み進めてほしい。

## 第2章｜非エンジニアのためのインストール完全ガイド

### 必要なもの

- PC（Mac or Windows）
- Anthropicのアカウント（無料で作れる）
- クレジットカード（Claude Code使用料：月20ドル〜）
- Node.js（後述、無料）

これだけ。

※ インストール方法は更新されることがある。うまくいかないときは、Anthropic の公式ドキュメント（Claude Code のページ）の手順も確認してほしい。

「ターミナルって何?」
って人、大丈夫。次で説明する。

### Macの場合

【ステップ1】ターミナルを開く

Macの右上の虫眼鏡（Spotlight）をクリック。
「ターミナル」と入力してEnter。

黒い画面が出てくる。これがターミナル。
怖がらなくていい。ただの"PCに命令を出す画面"。

【ステップ2】Node.jsをインストール

ターミナルに以下を1行ずつコピペしてEnter：

(1) Homebrewのインストール

```
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```

(2) Node.jsのインストール

```
brew install node
```

(3) 確認

```
node -v
```

「v20.x.x」みたいに表示されたらOK。

【ステップ3】Claude Codeのインストール

ターミナルに以下をコピペしてEnter：

```
npm install -g @anthropic-ai/claude-code
```

【ステップ4】起動

ターミナルに以下を入力：

```
claude
```

初回はAnthropicのアカウントログインを求められる。
画面の指示に従ってブラウザでログイン。

完了。これでClaude Codeが使える状態。

### Windowsの場合

【ステップ1】Node.jsをインストール

(1) https://nodejs.org/ にアクセス
(2) 「LTS」版をダウンロード
(3) ダウンロードしたファイルをダブルクリックして指示通りに進める

【ステップ2】コマンドプロンプトを開く

スタートメニューで「cmd」と検索→Enter

【ステップ3】Claude Codeのインストール

コマンドプロンプトに以下をコピペしてEnter：

```
npm install -g @anthropic-ai/claude-code
```

【ステップ4】起動

`claude` と入力してEnter。

初回ログインはMacと同じ。

### 詰まったとき

もし「Permission denied」みたいなエラーが出たら、
ターミナルに sudo を頭につけて再実行：

```
sudo npm install -g @anthropic-ai/claude-code
```

それでもダメなら、エラーメッセージをそのままClaudeに聞けば、たいてい解決の手がかりが出てくる。

## 第3章｜最初の30分で動かすための初期設定

### プロジェクトフォルダを作る

PCのデスクトップに「claude-projects」というフォルダを作る。
この中に、Claude Codeで作業するファイルを置いていく。

ターミナルで：

```
cd ~/Desktop/claude-projects
```

これで作業場所に移動できた。

### Claude Codeを起動

```
claude
```

これだけ。

起動すると、対話画面が出る。
ここに日本語で指示を打つだけ。

### 最初の指示テンプレ

慣れるまでは、こういう型で指示する：

```
【目的】（何を作りたいか）
【入力】（何を渡すか）
【出力】（何が欲しいか）
【制約】（やってほしくないこと）
```

たとえば：

```
【目的】noteの記事タイトル候補を10個出すツール
【入力】キーワード1つ（例：副業、AI）
【出力】タイトル候補10個（テキストファイルで保存）
【制約】30文字以内、煽りすぎない
```

これでClaude Codeがコードを書いて、ツールにしてくれる。

### 知っておくべき3つの基本コマンド

(1) /help
使えるコマンドの一覧が出る。

(2) /clear
今までの会話をリセット。新しいタスク始めるとき使う。

(3) Ctrl+C
処理を止めたいとき。

これだけ覚えとけば、最初は十分。

## 第4章｜今日から使える活用例10個（コード不要）

全部、Claude Codeに「これ作って」って言うだけ。
あなたがコードを書く必要はない。

指示文（プロンプト）と、出力イメージ・所要時間の目安を載せた。
所要時間は、作るツールやPCによって前後する。

### 活用例1｜noteタイトル量産ツール

```
キーワードを入力したら、noteで読まれやすいタイトルを20個生成するツールを作って。
出力は「titles.txt」というファイルに保存。
タイトルは数字入り、感情ワード入り、具体性高めの3パターン混ぜて。
```

出力イメージ：`titles.txt` に「会社員が昼休み5分で続けた副業メモ」「AIに丸投げして失敗した話」みたいなタイトルが20個並ぶ。
所要時間の目安：作成5分／実行1回30秒以内。

### 活用例2｜Threadsポスト下書き生成

```
テーマと文体サンプルを入力したら、Threadsの投稿文を10個作るツールを作って。
1投稿は500文字以内。
出力は「posts.md」に箇条書きで保存。
```

出力イメージ：`posts.md` に、自分の文体に寄せた500字以内の投稿が10本。
所要時間の目安：作成10分。

### 活用例3｜競合note記事の構成リサーチ

```
キーワードで検索した上位10記事のタイトルと見出し構造を抽出して、
よく使われる構成パターンをまとめるツール作って。
出力は「research.md」。
```

出力イメージ：「冒頭はどんな書き出しが多いか／第1章はどんな見出しが多いか」をまとめた分析メモ。
所要時間の目安：作成15分。

### 活用例4｜アフィリ案件の比較表自動作成

```
URLリストを渡すと、各案件の報酬額・条件・特徴を抽出してテーブルにするツール作って。
出力は「comparison.csv」。
```

出力イメージ：Excel/Numbersで開ける一覧表。案件ごとに報酬・条件・特徴が並ぶ。
所要時間の目安：作成15分。

### 活用例5｜Threadsのバズ投稿分析

```
保存した投稿のテキストファイルを読み込んで、
反応がよかった投稿の構造（フック、構成、文字数）を分析するツール作って。
出力は「analysis.md」。
```

出力イメージ：平均文字数、よく使われる書き出し、構成の型などの集計＋具体例。
所要時間の目安：作成10分。

### 活用例6｜ブログ記事の自動推敲

```
markdown形式の原稿を読み込んで、
冗長な部分・読みにくい部分を指摘し、修正案を出すツール作って。
出力は「edited.md」。
```

出力イメージ：原稿の横に「ここ重複」「この段落は2行短く」みたいな指摘＋直し済み版。
所要時間の目安：作成10分。

### 活用例7｜YouTubeネタリスト生成

```
ジャンルを入力したら、YouTubeで再生されやすい切り口を30個出すツール作って。
タイトル＋簡易構成のセットで、「ideas.md」に保存。
```

出力イメージ：タイトルと簡単な構成がセットになったネタが30本。
所要時間の目安：作成10分。

### 活用例8｜定型業務の自動化（議事録要約）

```
会議の文字起こしテキストを読み込んで、
「決定事項」「TODO」「次回確認事項」に分類して要約するツール作って。
出力は「summary.md」。
```

出力イメージ：長い議事録が、3カテゴリの短いまとめに。
※ 会社の情報を扱うときは、実名や社名を伏せる・会社のルールを確認するのが先。

### 活用例9｜Excelデータの自動集計

```
csvファイルを読み込んで、特定列の合計・平均・最大最小を計算し、
レポートを作成するツール作って。
出力は「report.md」。
```

出力イメージ：CSV→「合計◯／平均◯／最大◯／最小◯」のレポート。

### 活用例10｜LINE配信文のパターン生成

```
配信したい主題を入力すると、
「共感型」「実用型」「問いかけ型」の3パターンで配信文を生成するツール作って。
```

## 第5章｜社畜が片手間でやるための時間配分のコツ

### 結論：「指示する時間」と「確かめる時間」を分ける

社畜の最大の敵は時間。

俺も最初は「帰宅後に1〜2時間やる」と決めてた。
でも疲れてできない日が続いて、できない自分に落ち込んだ。
今は、昼休みや休憩の合間の5分・10分でやってる。そのほうが続いてる。

おすすめの分け方：

【スキマの5分】
前に作らせたツールの出力を確認するだけ。
気に入らなければ「修正して」と指示して、また次のスキマで確認。

【時間が取れる日だけ】
新しいツールを1つClaude Codeに指示。
動かしっぱなしにして、終わったら確認。

【週末に少し】
一週間で動かしたツールの結果をまとめて、noteやSNSに出す。

### やってはいけないこと

(1) 自分でコードを読もうとする
読まなくていい。動けばいい。
分からなかったらClaude Codeに「これ何してるか説明して」と聞けばいい。

(2) 完璧を目指す
ツールは"動く"が正義。"美しい"は不要。

(3) ツールをたくさん作りすぎる
最初は1つに絞る。動かして、使ってから次。

### 最初の7日間ロードマップ（社畜向け）

「で、結局何から作ればいいの?」って人へ。
最初の1週間の動き方を置いとく。

Day 1｜環境構築だけで終わってOK
- やること：第2章の手順通りにインストール、`claude` 起動まで
- ゴール：黒い画面で `claude` が動けばOK。何も作らなくていい。

Day 2｜活用例1（タイトル量産）を動かす
- やること：第4章・活用例1のプロンプトをそのままコピペ
- ゴール：`titles.txt` が手元に出力されてる状態。
- 重要：完璧を求めない。動いた=勝ち。

Day 3｜活用例2（Threads投稿）を動かす
- やること：第4章・活用例2のプロンプトをコピペ
- ゴール：`posts.md` に10投稿出力されてる状態。
- ボーナス：1本だけ、自分の言葉に直してThreadsに投稿してみる。

Day 4｜出力を「自分用」に調整する
- やること：Day2/3で作ったツールに「俺はこういう文体だから〜風に」と追加指示
- ゴール：自分の口調に近い出力になる。

Day 5｜noteを1本書いて公開（or 下書き保存）
- やること：Day2のタイトル＋Day3の文体で、noteを1本書く
- ゴール：実際にnoteに投稿（無料でOK）。
- 目的：「Claude Codeで作って→公開する」のフルサイクルを1回回す。

Day 6｜休む or 失敗ツールを修正
- やること：詰まったところをClaude Codeに「これ直して」と投げる
- ゴール：気が乗らなければ完全休養OK。継続が最優先。

Day 7｜振り返り＆来週の1ツール決定
- やること：1週間でどのツールが一番役に立ったかメモ
- ゴール：来週育てる"主力ツール"を1つ決める。

この7日間を終えた時点で、「Claude Codeに作業させて、自分は確認する」というリズムが手に入る。
あとはこれを続けるだけ。

## 第6章｜よくある詰まりポイントと解決法

### Q1：エラーが出た。どうすれば？

エラーメッセージをそのままClaude Codeにコピペして、
「これ直して」と言う。
多くの場合、これで直し方が出てくる。

### Q2：料金が怖い

最初は月20ドル（約3,000円）のプランで始めればいい。
慣れて使用量が増えてきたら、上のプランを検討する。

### Q3：どこまでClaude Codeに任せていい？

「アイデアと判断」は自分。
「作業」はClaude Codeに任せる。
出てきたものを確かめるのは、必ず自分。

### Q4：ツールが動いたあと、どう使えばいい？

cd でフォルダ移動して、

```
node ファイル名.js
```

で実行できる。
（Pythonの場合は `python ファイル名.py`）

これもClaude Codeに「使い方教えて」と聞けば
丁寧に教えてくれる。

### Q5：勉強しないとダメ？

まずは不要。
"使いながら覚える"が一番早い。

### Q6：従量課金で破産しないか不安なんだけど

最初はみんな気にする。
月額の定額プラン（Pro/Max）で始めれば、使いすぎで請求が膨らむ心配は小さい。

目安：
- ライトに使う → 月20ドルの定額プランから
- ガッツリ使う → 上の定額プランも検討
- API の従量課金 → 上級者向け。最初は不要

使用量は確認できる。週1で見るクセをつければ事故りにくい。

### Q7：会社にバレないか心配なんだけど

まず、会社のPC・会社のネットワーク・会社のメールアドレスは使わないこと。

- NG：会社支給PCで動かす／会社のメールでアカウントを作る／業務時間に動かす
- OK：私物PCで動かす／プライベートのメールで登録／休憩中・帰宅後・休日に動かす

ただし、これで「絶対にバレない」わけじゃない。
副業で収入が出ると、住民税の金額などから会社に伝わることがある。

いちばん大事なのは、自分の会社の就業規則を確認すること。
副業が禁止・届出制なら、それに従う。ここはClaude Code以前の話。

### Q8：家族にどう説明すればいい？

家庭それぞれだと思う。
「何をやっているか」「お金をどれくらい使うか」は、早めに話しておくほうが後で揉めにくい。

### Q9：途中で続かなくなりそうで怖い

"続かなくなる"の正体は、たいてい次の3つ：

(1) 1回でうまくいかせようとしてる
→ 最初の1週間は"動けばOK"。質は捨てる。

(2) 結果がすぐ出ると思ってる
→ 副業の売上は、すぐには出ないことが多い。俺もまだこれから。

(3) 時間を決めすぎてる
→ 俺は「毎日1〜2時間」をやめて、スキマの5分にしてから続くようになった。

死ぬこと以外はやり直せる。
続かなかった日があっても、また次のスキマから再開すればいい。
